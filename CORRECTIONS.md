# Corrections

When zWatchtower gets something wrong, it's fixed in the code and listed
here, newest first. Disputes are filed with the "Dispute a flag or fact"
issue form; each gets a public answer.

| Date (UTC) | What was wrong | Fix |
| --- | --- | --- |
| 2026-11-04 | 13 holder-reward alerts (runs 1486–1559: $ZDOG, $PI and one other coin) said shares didn't match Sapling's formula. Those coins pay holders in a basket of tokens: the pot is split into equal legs, one paid in ZEC and the rest swapped (through one-time wallets) into tokens such as $SAPLING, CYPH and hSOL. Sapling's payout rows list only the ZEC leg, which is why every share looked like a half, a quarter or a tenth. On chain, every holder got every token in proportion; holders whose token account had to be opened paid its cost (about 11,300 zat) from their share. The alerts were never posted to X; the Telegram channel wasn't running yet when they were raised. | The rewards check reads the other legs from the chain and checks them; the alerts are withdrawn as our misreading. Older runs with open alerts are now checked again each pass. |
| 2026-11-04 | Some Solana transactions now use version 1, which zWatchtower's lookups didn't ask for. Six keys-check runs (31 Oct – 2 Nov) failed on them, and the rewards check couldn't read one run. | Every lookup accepts version 1. |
| 2026-11-04 | Before the 5-minute server (until 3 Nov 13:48 UTC), the keys check read only the newest 100 vault-program transactions per run, while it ran every 30–77 minutes and the program does 180–350 an hour, so most routine vault transactions in between weren't read. Every multisig action was still caught (that account is quiet), and the admin wallet acted only through the multisig in that time, so no admin action went unseen; one multisig execute (Terminal settings, 3 Nov 13:10) was reported without its instruction's name. | The keys check reads every transaction since its last run, page by page, and fails loudly rather than skip any. |
| 2026-11-04 | The flywheel check compared Sapling's "bought back" headline (13.41 ZEC) with its burn list (4.73 ZEC) and reported a gap. The list only shows recent burns; the headline covers everything. Against every buyback the pot paid on chain (13.50 ZEC, 285 buybacks) the headline matches, apart from one buyback not listed yet. | The headline is compared with the pot's on-chain buybacks, counting buybacks Sapling hasn't listed yet. |
| 2026-11-03 | The first-buyer funding check flagged $1993 and $SHINU because several early buyers were first funded by the same wallet; that wallet funds wallets across many coins, like an exchange's withdrawal wallet. | Funders doing 1,000 transactions within a day no longer count, and labelled exchange wallets (starting with Binance 2, the one involved) never do. |
| 2026-11-03 | After moving to a server running Node 18, the rewards check couldn't hash snapshots ("crypto is not defined"), so no run was checked for about 30 minutes, and run 1524's open alert was marked resolved because the run went unchecked. | Hashing uses node:crypto, which works on every supported Node; an unchecked run now keeps its alert open. |
| 2026-11-02 | Coins launched from a shielded Zcash wallet (Sapling shows "shielded launch" as the creator) were counted as one creator. | Shielded launches now have no public creator; nothing is said about their buys or sells (aea3563). |
| 2026-11-02 | Launch reading stopped near the launch and could skip trades in the same second at a page edge, undercounting launch buys. No posted figure changed. | History is read to its start and the boundary second re-read (b7e8c31). |
| 2026-11-02 | The coins page showed Sapling's list market cap, which overstates coins still on their launch curve. | Each coin's own page is used (b7e8c31). |
